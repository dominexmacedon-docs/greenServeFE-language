gs_chemistry: Chemistry API

Complete source-grounded API reference for greenServeFE gs_chemistry: mole calculations, concentrations, acid-base chemistry, gas laws, stoichiometry, thermochemistry, kinetics and electrochemistry.

Module scope

Scalar chemistry calculations implemented in C, including amount of substance, solution concentration, acid/base logarithms, ideal gas relationships, balanced-equation ratios, reaction energy, first-order kinetics and the Nernst equation.

The module is a native C shared object. It adds an imported namespace to GSVE; it does not add keywords, alter the parser/compiler, or change the bytecode VM.

Build, install and import

Build the corresponding native module from the greenServeFE build repository using its matching manually triggered GitHub Actions workflow. The workflow's artifact is a build output; it is not automatically installed into every greenServeFE runtime.

# After placing the shared object in this directory:
export GREENSERVE_MODULE_PATH=/usr/local/lib/modules
export LD_LIBRARY_PATH=/usr/local/lib/modules:$LD_LIBRARY_PATH

# In a file named program.gsve:
import gs_chemistry;
print(gs_chemistry.info());

For a simple import, the VM searches the current directory, ./modules, the platform loader path, and directories listed in GREENSERVE_MODULE_PATH. The module must be named gs_chemistry.so in a searched location.

Constants and conventions

constants() returns R = 8.31446261815324, N_A = 6.02214076×10²³, F = 96485.33212, molar_volume_STP_L = 22.414 and pKw_at_25C = 14. The module's STP gas-volume helper uses 22.414 liters per mole.

Use SI-compatible units consistently: pressure in pascals with volume in cubic meters for the ideal gas law, temperature in kelvin, and energy/entropy units that agree in the Gibbs and Arrhenius equations. For molality, pass solvent mass in kilograms to obtain mol/kg.

The source implementation of first_order_half_life(initial, rate_constant) currently does not use its first argument; the result is ln(2)/k. This documentation preserves the actual two-argument export signature rather than presenting a guessed one-argument overload.

Practical GSVE examples

These examples use the implemented GSVE syntax: define declarations, func functions, semicolon-terminated statements, arrays, objects, for value in array iteration, and member calls.

import gs_chemistry;

define c = gs_chemistry.constants();
print(c.R);
print(c.N_A);

define sample_mass = 10;
define molar_mass = 58.44;
define amount = gs_chemistry.moles(sample_mass, molar_mass);
print(amount);

define solution_molarity = gs_chemistry.molarity(amount, 0.5);
print(solution_molarity);

define diluted = gs_chemistry.dilution_final_concentration(2, 0.1, 0.5);
print(diluted);

define ph_value = gs_chemistry.ph(0.000001);
define h_concentration = gs_chemistry.hydrogen_ion_concentration(6);
print(ph_value);
print(h_concentration);

define gas_volume = gs_chemistry.ideal_gas_volume(1, 101325, 273.15);
print(gas_volume);

define product_moles = gs_chemistry.stoichiometric_product_moles(2, 2, 1);
print(product_moles);

define remaining = gs_chemistry.first_order_remaining(100, 0.2, 5);
print(remaining);

define electrode = gs_chemistry.nernst_potential(1.1, 298.15, 2, 1);
print(electrode);

Validation, limits and numerical behavior

  • All required arguments must be finite GSVE numbers. Invalid types, missing arguments, invalid logarithm domains, zero denominators and invalid positive-domain inputs return null.
  • ph and poh require strictly positive concentrations. hydrogen_ion_concentration computes 10−pH.
  • ph_from_poh uses the 25 °C convention pH = 14 − pOH; it does not model temperature-dependent water ionization.
  • ppm assumes solute and solution quantities use the same mass unit. mass_percent also requires matching mass units.
  • gibbs_free_energy expects enthalpy and T×entropy in consistent energy units. arrhenius_rate_constant expects activation energy and R in matching units.
  • The module does not balance chemical equations, infer molecular formulas, track significant figures, or perform dimensional analysis. Stoichiometric coefficients must be supplied by the caller.
Native module functions validate their inputs and return GSVE null for invalid types, missing required numeric arguments, non-finite values, invalid domains, or resource-limit violations. Check inputs before using results in subsequent calculations.

VM and runtime relationship

GSVE source passes through the lexer, parser/AST, bytecode compiler and VM. Imported module functions are native function values stored in the module object. Calls such as gs_chemistry.info() are ordinary GSVE member access and function-call expressions; the VM dispatches them through the native function interface. Arrays and objects passed to native functions are GSVE runtime values, not C pointers exposed to the script.

Use greenServeFE --dump program.gsve to inspect compiled bytecode, greenServeFE --trace program.gsve to trace VM execution, and greenServeFE --profile program.gsve to collect opcode and function profiling data. These options inspect VM execution; they do not profile individual C instructions inside this module.
