gs_physics: Classical Physics API

Complete source-grounded API reference for greenServeFE gs_physics: kinematics, Newtonian mechanics, energy, fluids, thermodynamics, waves, gravitation and ideal-gas calculations.

Module scope

A collection of scalar physics formulas implemented in C. The functions accept finite numeric GSVE arguments and return numeric values or null when validation fails. SI units are recommended unless a function explicitly specifies degrees or Kelvin.

The module is a native C shared object. It adds an imported namespace to GSVE; it does not add keywords, alter the parser/compiler, or change the bytecode VM.

Build, install and import

Build the corresponding native module from the greenServeFE build repository using its matching manually triggered GitHub Actions workflow. The workflow's artifact is a build output; it is not automatically installed into every greenServeFE runtime.

# After placing the shared object in this directory:
export GREENSERVE_MODULE_PATH=/usr/local/lib/modules
export LD_LIBRARY_PATH=/usr/local/lib/modules:$LD_LIBRARY_PATH

# In a file named program.gsve:
import gs_physics;
print(gs_physics.info());

For a simple import, the VM searches the current directory, ./modules, the platform loader path, and directories listed in GREENSERVE_MODULE_PATH. The module must be named gs_physics.so in a searched location.

Physical quantities and units

Use a consistent unit system. The gravitational constant and gas constant in constants() use SI values. The work angle is the one explicit degree-based input. Thermodynamic temperatures used in Carnot and ideal-gas formulas should be absolute Kelvin values.

Important implementation detail: centripetal_force(mass, speed) returns m·v² and does not accept radius; reynolds_number(density, velocity, characteristic_length) returns ρvL and does not include viscosity. These exports are exactly as implemented and should not be mistaken for the complete textbook formulas.

Practical GSVE examples

These examples use the implemented GSVE syntax: define declarations, func functions, semicolon-terminated statements, arrays, objects, for value in array iteration, and member calls.

import gs_physics;

define constants = gs_physics.constants();
print(constants.g_standard);
print(constants.G);

define distance = 120;
define elapsed = 8;
define v = gs_physics.velocity(distance, elapsed);
print(v);

define a = gs_physics.acceleration(4, 20, 4);
define f = gs_physics.force(3, a);
print(f);

define kinetic = gs_physics.kinetic_energy(2, v);
define work_done = gs_physics.work(10, 5, 60);
print(kinetic);
print(work_done);

define pressure = gs_physics.pressure(100, 2);
define density = gs_physics.density(12, 3);
print(pressure);
print(density);

define orbit = gs_physics.orbital_speed(5.972e24, 6.371e6);
define escape = gs_physics.escape_speed(5.972e24, 6.371e6);
print(orbit);
print(escape);

define results = [v, a, f, kinetic, work_done, pressure, density];
for value in results {
    print(value);
}

Validation, limits and numerical behavior

  • Every required argument is a finite GSVE number. The module checks the required argument count and rejects non-number or non-finite values.
  • Division-by-zero and invalid physical domains return null, not infinity or NaN.
  • Several formulas only enforce the constraints visible in their implementation; the module is a formula utility, not a dimensional-analysis or unit-conversion engine.
  • final_velocity returns the positive square root of u² + 2as; it does not preserve a negative direction sign.
  • thermal_expansion_length returns the expanded length, not the change in length.
  • carnot_efficiency_percent expects cold and hot absolute temperatures with hot temperature greater than zero.
Native module functions validate their inputs and return GSVE null for invalid types, missing required numeric arguments, non-finite values, invalid domains, or resource-limit violations. Check inputs before using results in subsequent calculations.

VM and runtime relationship

GSVE source passes through the lexer, parser/AST, bytecode compiler and VM. Imported module functions are native function values stored in the module object. Calls such as gs_physics.info() are ordinary GSVE member access and function-call expressions; the VM dispatches them through the native function interface. Arrays and objects passed to native functions are GSVE runtime values, not C pointers exposed to the script.

Use greenServeFE --dump program.gsve to inspect compiled bytecode, greenServeFE --trace program.gsve to trace VM execution, and greenServeFE --profile program.gsve to collect opcode and function profiling data. These options inspect VM execution; they do not profile individual C instructions inside this module.
