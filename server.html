Reference documentation

greenServeFE HTTP Server and Networking API

Reference for the optional native server module: route registration, request and response objects, static serving, TLS options, HTTP client helpers and file/template utilities.

Module and runtime boundary

Import the optional native module with import server; when the matching server.so is installed. The build README distinguishes the core VM server name surface from the separately built host-runtime networking integration. The complete HTTP APIs below refer to the native server implementation, not a promise that every greenServeFE executable bundles networking automatically.

import server;
func home(req, res) {
    res.html("<h1>Hello from greenServeFE</h1>");
}
server.get("/", home);
server.serve(".", 8080, {static: false, host: "0.0.0.0"});

Request object

Handlers receive method, path, queryString, query, body, headers and params when a parameterized route matches. Colon segments create named parameters. Wildcard routes expose the matched value as req.params.wildcard. Query strings are available through req.query.

Response helpers

Reference response helpers include status, set, type, send, json, html, redirect, sendFile and render. The current build README additionally documents text, jsonp, noContent, download and cookie/header helpers. Check server.info() on the installed module to confirm optional capabilities.

func api(req, res) {
    res.status(200);
    res.set("X-App", "greenServeFE");
    res.json({method: req.method, path: req.path, query: req.query});
}
server.get("/api/info", api);

Serve options

Documented options include index, static, cors, notFound, host, backlog, max_requests, protocol, cert and key. Reference defaults: host 0.0.0.0, port 8080, index index.html.

server.serve(".", 8443, {
    protocol: "https",
    cert: "server.crt",
    key: "server.key",
    index: "index.html",
    static: true
});

Additional exported helpers

The C initializer exports the following names in addition to route registration:

info, tls, features, request, http_get, https_get, http_post, http_put, http_patch, http_delete, http_options, read_file, write_file, render, url_encode, json_escape.

Security and deployment

  • Never commit TLS private keys.
  • Validate request parameters and bodies before using them.
  • Constrain file paths and avoid exposing file helpers to untrusted input.
  • Test the installed shared object and runtime behavior before production deployment.
The full native HTTP server is a separately built integration. The module build workflow and runtime tests determine which additions are available in a given package version.
