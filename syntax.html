greenServeFE Language Syntax

A practical, implementation-aligned reference to the GSVE language accepted by the greenServeFE lexer, parser, compiler and bytecode virtual machine. It covers source syntax, runtime values, control flow, functions, classes, imports, built-ins and the native module boundary.

Version and scope. This reference describes the source currently present in greenServeFE-build (runtime identifies itself as 1.0.6). Native modules are independently compiled shared libraries. An API appearing in a module page is available only when its matching module is built and installed.

1. Quick start

Save source in a file ending in .gsve. The runtime reads the file, tokenizes it, parses an AST, compiles bytecode and executes that bytecode in the VM.

# hello.gsve
define language = "greenServeFE";
print("Hello from " + language);

func square(value) {
    return value * value;
}

print(square(9));
greenServeFE hello.gsve
greenServeFE --version
greenServeFE --dump hello.gsve
greenServeFE --trace hello.gsve
greenServeFE --profile hello.gsve

Statements may be separated by newlines or semicolons. Blocks use braces. The language uses define for declarations and func for function declarations; it does not use JavaScript's let, const or function declaration keywords.

2. Lexical rules

Identifiers

Identifiers begin with an ASCII letter or underscore and continue with letters, digits or underscores. Examples: name, _cache, item2, total_price. Keywords are case-sensitive.

Comments and whitespace

# This is a comment. It continues to the end of this line.
define total = 10; # inline comment

Spaces, tabs, carriage returns and line breaks separate tokens. A # begins a comment outside a quoted string. The lexer accepts both single-quoted and double-quoted strings.

String escapes

EscapeMeaning
\\nLine feed
\\rCarriage return
\\tTab
\\\\Backslash
\\"Double quote
\\'Single quote
define message = "first line\nsecond line";
define label = 'Dominex\'s program';
print(message);
print(label);

3. Values and literals

The runtime value model includes null, number, boolean, string, array, object, user function, native function and iterator.

Numbers support integer-looking and decimal notation. There is no separate integer type in the runtime representation.

4. Expressions and operators

Arithmetic

define a = 17;
define b = 5;
print(a + b);  # 22
print(a - b);  # 12
print(a * b);  # 85
print(a / b);  # 3.4
print(a % b);  # remainder

Comparison and equality

print(5 == 5);
print(5 != 3);
print(3 < 8);
print(3 <= 3);
print(9 > 4);
print(9 >= 9);

Logical and unary operators

define enabled = true;
define ready = enabled && (4 > 2);
define blocked = false || !ready;
define negative = -12;
define positive = +12;

&& and || short-circuit: the right-hand expression is skipped when the left side already determines the result. Logical results are booleans. Unary ! negates truthiness; unary - negates a number. Unary + is parsed as a unary operator and leaves its operand unchanged.

GroupOperators
Grouping / postfix( ), function call (), index [], member .
Unary!, -, +
Multiplicative*, /, %
Additive+, -
Relational<, <=, >, >=
Equality==, !=
Logical AND&&
Logical OR||
Assignment= (statement/expression assignment form)

Parentheses can make grouping explicit. Addition also supports string concatenation through the runtime's value operation.

5. Declarations and assignment

define username = "Ada";
define score = 100;
define active = true;

score = score + 5;
username = "Grace";
print(username);
print(score);

define name = expression; declares a binding in the current lexical environment. Assignment updates a variable binding or a nested collection target.

define profile = {name: "Ada", stats: {visits: 1}};
profile.name = "Grace";
profile.stats.visits = 2;

define values = [10, 20, 30];
values[1] = 99;
Use define when introducing a variable. Use = to assign a new value to an existing binding, object member or array index.

6. Arrays and objects

Arrays

define colors = ["green", "blue", "gold"];
print(colors[0]);
print(len(colors));
push(colors, "silver");
define last = pop(colors);
print(last);

Array indexes are zero-based. Index expressions may be computed. Arrays can contain mixed values and nested arrays/objects.

Objects

define account = {
    name: "Ada",
    active: true,
    balance: 125.50
};
print(account.name);
print(account["balance"]);
account.active = false;

define key = "name";
print(account[key]);

Object keys may be identifiers or quoted strings. Values are arbitrary expressions. Dot access uses a literal member name; bracket access uses a computed key.

Nested values and iteration

define orders = [
    {id: 101, items: ["book", "pen"]},
    {id: 102, items: ["laptop"]}
];

for (order in orders) {
    print(order.id);
    for (item in order.items) {
        print(item);
    }
}

Arrays, objects and strings are iterable. Array iteration yields elements; object iteration yields keys; string iteration yields characters.

7. Control flow

if / else if / else

define score = 82;
if (score >= 90) {
    print("excellent");
} else if (score >= 70) {
    print("pass");
} else {
    print("retry");
}

while

define count = 0;
while (count < 3) {
    print(count);
    count = count + 1;
}

for / in

for (number in [10, 20, 30]) {
    print(number);
}

for (key in {host: "localhost", port: 8080}) {
    print(key);
}

break and continue

for (number in [1, 2, 3, 4, 5]) {
    if (number == 2) {
        continue;
    }
    if (number == 5) {
        break;
    }
    print(number);
}

break exits the nearest loop. continue advances the nearest loop to its next iteration.

8. Functions, return values and closures

Named function declaration

func add(a, b) {
    return a + b;
}
print(add(12, 8));

Function expressions and values

define multiply = func(a, b) {
    return a * b;
};
define operation = multiply;
print(operation(6, 7));

Return and omitted arguments

func greet(name) {
    if (name == null) {
        return "Hello";
    }
    return "Hello " + name;
}
print(greet());
print(greet("Ada"));

A function that reaches its closing brace returns null. A missing positional argument is supplied as null. Validate arguments when a function requires them.

Closures

func make_counter() {
    define count = 0;
    func next() {
        count = count + 1;
        return count;
    }
    return next;
}
define counter = make_counter();
print(counter());
print(counter());

Nested functions capture the lexical environment where they are created. Captured bindings can be read and updated after the outer function has returned.

Recursion

func factorial(n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
print(factorial(5));

9. Class descriptors and instances

The runtime includes lightweight class descriptors, default fields, methods, inheritance, instance creation and instanceof. Methods are ordinary functions: pass the instance explicitly as the first parameter (commonly named self). This is not an automatic receiver-binding or constructor-dispatch system.

define Animal = class({
    fields: {name: "unknown"},
    methods: {
        describe: func(self) {
            return "Animal: " + self.name;
        }
    }
});

define Dog = class({
    extends: Animal,
    fields: {kind: "dog"},
    methods: {
        speak: func(self) {
            return self.name + " says woof";
        }
    }
});

define pet = new Dog();
pet.name = "Rex";
print(pet.describe());
print(pet.speak());
print(pet instanceof Dog);

Class construction is provided by core built-ins rather than a separate class-declaration keyword. Consult the current runtime examples before relying on advanced inheritance behavior.

11. Imports and native modules

Import a module namespace

import gs_math;
print(gs_math.sqrt(81));

Import selected names

from gs_math import sqrt, clamp;
print(sqrt(144));
print(clamp(120, 0, 100));

Import statements are compiled to module-loading operations. The VM dynamically loads a shared object, resolves the initializer symbol greenServeFE_module_init, and exposes the returned object under the module name. Imported members are then accessed through normal member lookup.

Module search path

export GREENSERVE_MODULE_PATH=/usr/local/lib/modules
export LD_LIBRARY_PATH=/usr/local/lib/modules:$LD_LIBRARY_PATH

A typical Linux installation places shared objects such as /usr/local/lib/modules/gs_math.so and /usr/local/lib/modules/server.so in the module search directory. Local module paths are also recognized by the loader. Ensure the shared object matches the runtime's native ABI.

Native module ABI

GSValue greenServeFE_module_init(const GSNativeAPI *api);

A module initializer receives the versioned GSNativeAPI table and returns a GSVE object containing exported native functions. The API provides value constructors, retain/release and copy operations, array/object access, conversions, truthiness, printing and a callback bridge for calling GSVE functions. Current ABI version is 1. Modules should use the public API rather than private VM structures.

Server and HTML construction

import server;

func home(req, res) {
    res.html("
Hello from greenServeFE
");
}

server.get("/", home);
server.serve(".", 8080, {host: "0.0.0.0", static: false});

The server and construct APIs are native modules with their own references. Check Server and Construct for exact exported methods and current build status. The server module's availability depends on its corresponding native build and installation; the VM core alone is not a full HTTP server.

12. How source becomes executable

Execution pipeline
.gsve source
  → lexer (tokens with source locations)
  → parser (AST)
  → compiler (GSCode)
  → bytecode instruction stream
  → VM frames + operand stack + environments
  → runtime values and native calls

Lexer and parser

The lexer recognizes identifiers, numeric and string literals, keywords, punctuation, arithmetic/comparison/logical operators and source line/column positions. The parser builds expression and statement nodes for declarations, assignments, blocks, conditionals, loops, functions, calls, arrays, objects, indexing, members and imports.

Compiler and code objects

The compiler translates AST expressions and statements into instructions. A GSCode stores instructions, constants, name references, child function code objects and parameter metadata. Function bodies are compiled into child code objects; function creation captures the current lexical environment.

Virtual machine

The VM executes instructions using an instruction pointer, operand stack and call frames. Frames refer to a code object and lexical environment. Environments link to parent environments for lexical lookup and closure capture. Runtime values include reference-counted strings, arrays, objects, functions and iterators.

Bytecode operations

The instruction set includes loading constants/names, storing names, stack operations, arithmetic, comparisons, unary operations, jumps, conditional jumps, calls, returns, array/object construction, member/index get/set, function creation, imports, iterator initialization/advance and halt.

Use --dump to inspect compiled instructions, --trace to observe execution and --profile to collect runtime profiling data.

14. Grammar and compiler-supported forms

This section describes the forms represented by the current lexer, parser and compiler. It is intentionally narrower than JavaScript, Python or C: syntax from those languages is not automatically accepted by GSVE.

ConstructAccepted formNotes
Declarationdefine name = expression;Introduces a binding in the current environment.
Named functionfunc name(a, b) { ... }Parameters are positional.
Anonymous functionfunc(a, b) { ... }Can be assigned, passed or returned.
Conditionalif (condition) { ... } else { ... }else if is supported through nested conditional branches.
Loopwhile (condition) { ... }Condition is evaluated before each iteration.
Iterationfor (item in iterable) { ... }Iterates arrays, object keys and string characters.

Statement separators and blocks

Newlines and semicolons separate statements. Braces delimit blocks and object literals. Parentheses group expressions and surround conditions, loop headers and function arguments. Commas separate function parameters, call arguments, array items and object entries.

Current syntax exclusions

The current token and AST definitions do not define dedicated syntax for let, const, var, function, arrow functions, classes declared with a class keyword, ternary expressions, switch, try/catch, exceptions, async/await, generators, template literals, increment/decrement operators, compound assignment operators, or type annotations. Use the documented GSVE forms instead of assuming these constructs work.

15. Bytecode instruction reference

The compiler emits GSInstr records. Each instruction stores an 8-bit opcode, a signed 32-bit argument and the source line. A GSCode object owns its instruction array, constants, name table, child function code objects and parameter count.

Opcode familyInstructionsRole
Constants and namesNOP, LOAD_CONST, LOAD_NAME, STORE_NAME, POP_TOPLoad constants and lexical bindings, store values, and discard expression results.
ArithmeticADD, SUB, MUL, DIV, MOD, NEGNumeric operations and addition (which also supports string concatenation through the value layer).
Comparisons and logicNOT, EQ, NE, LT, LE, GT, GE, AND, ORUnary truthiness negation, equality, ordering and logical operations.
Control flowJUMP, JUMP_IF_FALSE, JUMP_IF_TRUEImplement branches, loops, break/continue targets and short-circuit evaluation.
Calls and functionsCALL, RETURN, MAKE_FUNCTIONInvoke native/user functions, return from frames and create closures.
CollectionsBUILD_ARRAY, BUILD_OBJECT, GET_INDEX, SET_INDEX, GET_MEMBER, SET_MEMBERConstruct arrays/objects and read or update indexed/member values.
ModulesIMPORT, FROM_IMPORTLoad a module object or selected exports.
Iteration and terminationITER_INIT, ITER_NEXT, HALTCreate an iterator, advance it or stop execution.

Logical && and || are compiled as conditional jumps so the right-hand expression is skipped when its result is unnecessary. The VM also has logical opcode handlers, but the compiler's short-circuit path uses jumps and boolean normalization. Use greenServeFE --dump program.gsve to inspect the actual instruction stream generated for a program.

16. Runtime values, environments and calls

  • Value representation: the VM's tagged GSValue union represents null, double-precision numbers, booleans, strings, arrays, objects, user functions, native functions and iterators.
  • Lexical environments: each environment stores named bindings and may point to a parent environment. Name lookup and assignment walk this parent chain.
  • Closures: creating a function captures the current environment. Calling it creates a child environment, binds positional parameters, and executes the function's code object in a new VM frame.
  • Frames and stack: a frame tracks its code object, instruction pointer, operand-stack base and lexical environment. Calls to native functions use the native function pointer; user functions push VM frames.
  • Missing values: omitted positional arguments are bound to null. A function body receives an implicit null return if control reaches its end.
  • Iteration: array iterators yield values in index order, object iterators yield property names, and string iterators yield one character at a time.
  • Object access: a missing object property or out-of-range array/string index produces null in the current value access implementation.
  • Class model: class descriptors and instances are objects marked with runtime metadata. Inherited default fields are cloned for instances; methods remain ordinary function values and receive self explicitly.
GSVE is dynamically typed. The VM does not provide static type checking, a garbage-collected heap, process isolation or a security sandbox. Treat scripts and native modules as trusted executable code.

17. Native module ABI and loader

Export contract

#include "module.h"

GSValue greenServeFE_module_init(const GSNativeAPI *api) {
    GSValue exports = api->object();
    /* Create native functions with api->native(...),
       then add them to exports with api->object_set(...). */
    return exports;
}

The initializer symbol is greenServeFE_module_init; the current ABI version is GSFE_MODULE_ABI_VERSION 1. The initializer receives a GSNativeAPI function table. It returns one GSVE object whose properties form the module's public namespace. A module that returns a non-object or omits the initializer cannot be imported successfully.

Native API services

The ABI exposes constructors for null, number, boolean, string, object, array and native-function values; value copy/retain/release; array and object access; C-string, truthiness and numeric conversions; value printing; and a callback bridge for invoking GSVE functions from native code. Use the ABI table instead of depending on private VM structures.

Module lookup order

For a simple import such as import gs_math;, the loader tries the current-directory path ./gs_math.so, then ./modules/gs_math.so, then gs_math.so through the platform loader, followed by each colon-separated directory in GREENSERVE_MODULE_PATH. If the import string contains a slash or already ends in .so, it is treated as a direct path. Loaded modules are cached by import name for the lifetime of the VM.

export GREENSERVE_MODULE_PATH=/usr/local/lib/modules
export LD_LIBRARY_PATH=/usr/local/lib/modules:$LD_LIBRARY_PATH

# Example source file
import gs_math;
print(gs_math.sqrt(81));

The loader opens modules with dlopen, resolves the initializer with dlsym, and keeps the shared-library handle alive until VM teardown. A missing library, missing initializer or invalid return value is reported as a runtime module-loading error.

21. Current implementation boundaries

  • The accepted source extension is .gsve.
  • The language is dynamically typed; numbers are represented as doubles.
  • Declarations use define; functions use func; blocks use braces.
  • Function parameters are positional. Missing arguments become null; there is no documented default-parameter or variadic-parameter syntax.
  • Class support is a lightweight descriptor/instance model. Methods receive self explicitly; do not assume automatic method binding.
  • Native modules are external shared objects using ABI version 1, not keywords built into the language.
  • HTTP, HTML, database, numerical and AI capabilities depend on the corresponding module being available in the runtime's module path.
  • The current core VM and module APIs should be treated according to the implementation and module-specific documentation; do not infer unsupported syntax from another language.
