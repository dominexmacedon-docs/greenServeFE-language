gs_signal: Digital Signal Processing API

Complete source-grounded API reference for greenServeFE gs_signal: sampled waveform generation, measurements, normalization, moving averages, convolution, correlation, DFT, spectrum, differentiation, integration and RC low-pass filtering.

Module scope

Discrete-time signal generation and processing implemented in native C. The module accepts GSVE arrays of finite numeric samples and returns scalar measurements, transformed arrays, or arrays of spectral-bin objects.

The module is a native C shared object. It adds an imported namespace to GSVE; it does not add keywords, alter the parser/compiler, or change the bytecode VM.

Build, install and import

Build the corresponding native module from the greenServeFE build repository using its matching manually triggered GitHub Actions workflow. The workflow's artifact is a build output; it is not automatically installed into every greenServeFE runtime.

# After placing the shared object in this directory:
export GREENSERVE_MODULE_PATH=/usr/local/lib/modules
export LD_LIBRARY_PATH=/usr/local/lib/modules:$LD_LIBRARY_PATH

# In a file named program.gsve:
import gs_signal;
print(gs_signal.info());

For a simple import, the VM searches the current directory, ./modules, the platform loader path, and directories listed in GREENSERVE_MODULE_PATH. The module must be named gs_signal.so in a searched location.

Sampling model and result shapes

Waveform generators compute the sample count as ceil(sample_rate_hz × duration_seconds). Samples are generated at t = index / sample_rate_hz. The waveform APIs return arrays of numbers. dft returns an array of objects with real, imag, magnitude and phase; spectrum returns objects with frequency_hz and magnitude.

For dft and spectrum, only bins from zero through the Nyquist-side index floor(N/2) are returned. The implementation uses a direct O(N²) transform, not an FFT.

The hard sample-array cap is 4096 elements. Generated waveforms and output arrays are bounded by this limit. The direct DFT can become expensive well before the maximum length; use modest sample counts for interactive examples.

Practical GSVE examples

These examples use the implemented GSVE syntax: define declarations, func functions, semicolon-terminated statements, arrays, objects, for value in array iteration, and member calls.

import gs_signal;

define samples = gs_signal.sine(5, 100, 0.2, 2);
print(gs_signal.info());

print(gs_signal.mean(samples));
print(gs_signal.rms(samples));
print(gs_signal.peak(samples));
print(gs_signal.peak_to_peak(samples));
print(gs_signal.energy(samples));

define normalized = gs_signal.normalize(samples);
define smooth = gs_signal.moving_average(samples, 5);
print(normalized);
print(smooth);

define impulse = [1, 0, 0, 0];
define kernel = [0.25, 0.5, 0.25];
define filtered = gs_signal.convolve(impulse, kernel);
print(filtered);

define bins = gs_signal.dft(samples);
print(bins[0].magnitude);

define spectrum = gs_signal.spectrum(samples, 100);
print(spectrum[0].frequency_hz);

define slope = gs_signal.derivative(samples, 100);
define area = gs_signal.integral(samples, 100);
print(slope);
print(area);

define low = gs_signal.lowpass_rc(samples, 10, 100);
print(low);

Validation, limits and numerical behavior

  • Sample inputs must be non-empty arrays containing only finite numbers. The maximum input length is 4096 samples.
  • Waveform arguments require frequency ≥ 0, sample rate > 0 and duration > 0; optional amplitude defaults to 1. Generated sample count must be between 1 and 4096.
  • moving_average requires an integer window size from 1 through the sample count and returns only complete windows.
  • convolve returns full linear convolution and rejects a result longer than 4096 values.
  • correlation requires equal-length arrays and nonzero variance in both signals; otherwise it returns null.
  • normalize returns null for an all-zero input because its peak magnitude is zero.
  • integral requires an explicit positive sample rate. derivative and spectrum default their sample rate to 1 when omitted.
  • lowpass_rc requires 0 < cutoff frequency < Nyquist frequency (sample_rate/2). Its implementation is a first-order recursive RC smoothing filter.
  • The DFT and convolution implementations are direct algorithms; there is no FFT acceleration, streaming interface, windowing, or anti-aliasing stage in this module.
Native module functions validate their inputs and return GSVE null for invalid types, missing required numeric arguments, non-finite values, invalid domains, or resource-limit violations. Check inputs before using results in subsequent calculations.

VM and runtime relationship

GSVE source passes through the lexer, parser/AST, bytecode compiler and VM. Imported module functions are native function values stored in the module object. Calls such as gs_signal.info() are ordinary GSVE member access and function-call expressions; the VM dispatches them through the native function interface. Arrays and objects passed to native functions are GSVE runtime values, not C pointers exposed to the script.

Use greenServeFE --dump program.gsve to inspect compiled bytecode, greenServeFE --trace program.gsve to trace VM execution, and greenServeFE --profile program.gsve to collect opcode and function profiling data. These options inspect VM execution; they do not profile individual C instructions inside this module.
